# Enterprise AI Skills（企业 AI 技能包）

**由前麦肯锡顾问打造的 13 套咨询框架，封装成即插即用的 Claude 技能。** 议题树、决策备忘录、麦肯锡风格图表、完整的幻灯片流水线——这些策略师、产品经理和运营负责人本来就要用的东西，现在一句提示词就能跑起来。

![实战示例：我该选哪项运动？](assets/hero.gif)

> 一段 30 秒的完整演示：拿一个真实的个人问题（*“我该选哪项运动？”*），自上而下地跑通其中 4 个技能——**议题树 → 故事线 → 图表 → 幻灯片流水线**——最终产出一份 8 页、图表原生可编辑的幻灯片。
>
> 完整实战示例（含提示词）：[`examples/which-sport-to-pick-up/`](examples/which-sport-to-pick-up/)。

## 30 秒上手

打开 Claude（或任何加载了这些技能的大模型），粘贴以下内容：

```text
帮我做一份麦肯锡风格的幻灯片，主题是我正在纠结的一个决策：
"我该选哪项运动：匹克球、网球，还是跑步？"

跑完整的自上而下工作流：
1. 用 issue-tree-builder 分解成 MECE 分支
2. 用 storyline-builder 转成 8 个论点式幻灯片标题
3. 用 mckinsey-charts 制作数据页图表（柱状图+标注、瀑布图）
4. 用 deck-pipeline（策略师 → 构建者 → 评审者 → 修复者）生成最终 .pptx
```

你会得到与上面 GIF 相同的流程，以及一份可以打开编辑的真实 `.pptx` 文件。把问题换成你真正关心的：*“我该投入哪个副业？”、“该接受这份工作吗？”、“我们该搬去哪里？”*——同样的工作流，你的决策。

## 安装

- **Claude Code：** 克隆本仓库——在该目录下工作时技能会自动加载。
- **Claude.ai：** 下载任意技能的 `.skill` 文件 → 设置 → 技能 → 添加技能。
- **任何大模型：** 把 `SKILL.md` 的内容复制到对话中作为上下文。

```bash
git clone https://github.com/sruthir28/enterprise-ai-skills.git
```

除 Claude 本身外无需任何依赖。如需在本地生成 `.pptx` 文件，幻灯片流水线（`deck-pipeline` + `mckinsey-charts`）需要 Python 3.9+ 和 `python-pptx`——参见 [`examples/which-sport-to-pick-up/build.py`](examples/which-sport-to-pick-up/build.py)。

## 技能一览

### 预检类
先审计你掌握的信息，再做结构化——防止下游技能编造数字或放大错误数字。

| 技能 | 功能 | 最适合 |
|-------|-------------|----------|
| [Context Intake（信息预检）](context-intake/SKILL.md) | 把每条主张标注为已验证 / 假设 / 未知，标记矛盾点，就影响最大的缺失字段提问 | 输入质量不确定或 stakes 较高时，在任何技能之前运行 |

### 思维类
麦肯锡基本功——界定问题、承诺答案、从杂乱输入中提炼“所以呢”。

| 技能 | 功能 | 最适合 |
|-------|-------------|----------|
| [SCPR Framework（SCPR 框架）](scpr-framework/SKILL.md) | 用情境-冲突-问题-建议的结构组织论证 | 执行摘要、备忘录、战略建议 |
| [Issue Tree Builder（议题树构建器）](issue-tree-builder/SKILL.md) | 把问题拆解成 MECE 组成部分 | 分析、案例准备、工作计划 |
| [Hypothesis Tree（假设树）](hypothesis-tree/SKILL.md) | 第一天就承诺一个答案，并设计能推翻它的测试 | 任何一上来容易“大海捞针”的分析 |
| [Synthesis（综合提炼）](synthesis/SKILL.md) | 把一堆访谈 / 记录 / 研究资料变成 3 条带证据和“所以呢”的洞察 | 客户访谈、问卷调研、研究资料堆之后 |
| [Prioritization（优先级排序）](prioritization/SKILL.md) | 用 RICE、影响/投入、价值/复杂度给功能打分 | 路线图决策、功能取舍 |
| [AI Use-Case Scorer（AI 用例评分器）](ai-use-case-scorer/SKILL.md) | 按价值 × 可行性 × 安全性给 AI 用例打分；分成“立即做 / 本季度 / 搁置 / 回避” | 个人 AI 路线图、“下一个该 AI 化什么” |
| [Data Insights（数据洞察）](data-insights-simple/SKILL.md) | 分析任意数据集并用通俗英语回答关键问题 | 不当数据科学家也能快速分析 |

### 写作类
答案先行、证据密集、逼出决策。

| 技能 | 功能 | 最适合 |
|-------|-------------|----------|
| [Decision Memo Builder（决策备忘录生成器）](decision-memo-builder/SKILL.md) | 一页备忘录逼出一个“是/否”（情境 → 选项 → 建议 → 风险 → 诉求） | 领导层决策、范围裁剪、自建/外购决策 |
| [Top-Down Memo（自上而下备忘录）](top-down-memo/SKILL.md) | 用金字塔原理答案先行写作——结论、3 个论点、证据 | 给高管的邮件、简报、必须一击即中的 Slack 消息 |
| [Storyline Builder（故事线构建器）](storyline-builder/SKILL.md) | 构建每句话 = 一页标题的幻灯片叙事 | 幻灯片、路演、董事会汇报 |

### 会议与人际类
政治决定成败的地方。

| 技能 | 功能 | 最适合 |
|-------|-------------|----------|
| [Meeting Prep Kit（会议准备工具包）](meeting-prep-kit/SKILL.md) | 为你主导的任何会议准备预读材料 + 议程 + 发言要点 + 异议应对 | 高管评审、利益相关方提案、范围谈判 |
| [Stakeholder Map（利益相关者地图）](stakeholder-map/SKILL.md) | 把与会者映射到权力/利益矩阵，标注每个人的立场 + 一个影响动作 | 跨部门决策、组织调整、产品发布 |
| [Workshop Designer（工作坊设计器）](workshop-designer/SKILL.md) | 设计半天或全天的会议，最终产出已承诺的成果物 + 责任人 | 高管务虚会、领导层对齐、季度规划 |

### 幻灯片类
原生、可编辑的 PowerPoint——不用 Gamma，不用图片。

| 技能 | 功能 | 最适合 |
|-------|-------------|----------|
| [McKinsey Charts（麦肯锡图表）](mckinsey-charts/SKILL.md) | 三款主力图表（柱状图+标注、堆叠时间序列、瀑布图），均为原生 python-pptx 对象 | 任何需要达到“项目经理已审”水准的图表，而不是 Excel 默认样式 |
| [Deck Pipeline（幻灯片流水线）](deck-pipeline/SKILL.md) | 4 智能体流水线：策略师 → 构建者 → 评审者 → 修复者。调用故事线 + 图表产出经得起评审的幻灯片。 | 董事会幻灯片、战略汇报、任何高风险页面 |

### 智能体
| 技能 | 功能 | 最适合 |
|-------|-------------|----------|
| [McKinsey Critic（麦肯锡评审）](mckinsey-critic/SKILL.md) | 像麦肯锡项目经理一样评审幻灯片和文档——打分、标记问题、给出前 3 条修改建议 | 任何成果交给利益相关方之前的质量关卡 |

## 技能如何组合使用

大多数实际工作会组合使用其中 2–3 个技能。常见的组合栈：

- **任何高风险工作之前：** 信息预检 →（下方任意组合）——先验证输入，避免下游技能编造或放大错误数字

- **客户研究 → 备忘录：** 综合提炼 → 自上而下备忘录（或决策备忘录）→ 麦肯锡评审
- **战略问题 → 建议：** 议题树 → 假设树 → 跑测试 → 决策备忘录
- **涉及政治博弈的重大决策：** 利益相关者地图 → 决策备忘录 → 会议准备工具包（用于每次 1:1）
- **董事会幻灯片（上面的 GIF）：** 议题树 → 故事线构建器 → 图表 → 幻灯片流水线 → 麦肯锡评审
- **务虚会或对齐工作坊：** 工作坊设计器 → 会议准备工具包（会前 1:1）→ 工作坊执行 → 自上而下备忘录（会后发送）

## 它是什么，不是什么

**是：** 一个由 13 个“带结构的提示词”组成的库，把模糊的战略请求变成决策形状的成果物。每个技能封装了一个具体的咨询动作（MECE 拆解、第一天假设、金字塔原理等），让 Claude 不必每次重新发明结构。

**不是：** 聊天机器人、UI，或泛泛的“AI 办公”提示词。没有模型微调。这些技能之所以有效，是因为结构正确，而不是因为模型特别。
